# @dkcli/cli

## 0.4.0

### Minor changes

- Add `dk project verify`, `qualify`, and `patch` for portable theme projects with fonts, token overrides, revisions, reviews, and content identity. Qualification requests can select named cases, Chromium, Firefox, WebKit, browser color preferences, CSS zoom, and the same-origin font fixture. Reject invalid options and receipts that substitute requested conditions.
- Use the public core engine for the CLI and workbench. Correct descending Fibonacci steps and compounded optical circle sizing.

### Patch changes

- Report every declared mathematical proof, per-width result, and coverage gap. Apply explicitly authored responsive surface caps, retain their preferred widths and assumptions, and preserve unresolved line-width findings. Strict commands write their artifacts before returning failure.
- Bundle component verification in the standalone CLI. Check the packed executable and interactive Svelte and SvelteKit consumers during release qualification.
- Detect low-contrast CSS text when a block begins with whitespace and a color declaration. Reject invalid fluid viewport ranges, combine optical icon transforms, and preserve alias-to-alias CSS variable references.
- Distinguish invalid item-array shapes from malformed JSON in `dk future`. Use direct command help and label source audit scores as heuristic evidence.

## 0.3.1

### Patch changes

- Ship security hardening for public CLI and package APIs.

  - Bind stored DKCMS sessions to their original base URL before authenticated requests.
  - Escape `dk future` generated CSS selectors and comments.
  - Validate component specs and use safer maps during recipe compilation.
  - Reject unsafe CSS custom property names and declaration-breaking values during token and recipe CSS emission.
  - Sanitize public component href props before rendering links.
  - Pin the release workflow Changesets action to an immutable commit.

## 0.3.0

### Minor changes

- Split the public CLI/package workspace from the private website and runtime surface.

  The CLI package treats hosted DKCMS features as a public client only, removes rendered audit runtime coupling from the public command surface, and adds package-content checks for private server, route, worker, deploy, and runtime-token references.

  The component package build/test configuration avoids generated Svelte package output during Vitest collection and compiles Svelte component tests through the Svelte Vite plugin.
